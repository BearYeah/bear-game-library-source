# 下载设计：资料如何变成文件

本文只解释数据结构和处理流程，不列出 manifest、depot key 或 Lua 的获取渠道。仓库没有附带游戏资料和运行中的资料服务。

## 各项资料的作用

| 内容 | 作用 |
| --- | --- |
| AppID / 游戏信息 | 确定游戏、安装目录、分支和适用的 depot |
| Depot ID | 标识一组可安装内容 |
| Manifest GID | 指定该 depot 的一个具体版本 |
| Manifest | 描述文件名、大小、标志、分块摘要和写入偏移 |
| Depot key | 解密相应 depot 的加密文件名或内容块 |
| Lua | 可选的文本声明格式；解析声明，不运行脚本 |

这些内容必须对应同一版本。只有清单而没有所需密钥，不能完成相应内容的解密。密钥本身也不包含文件列表。

## 处理顺序

1. 从使用者提供的本地资料或配置接口读取游戏信息。
2. 选择 Windows public 和目标语言对应的 depot。
3. 读取对应版本的 manifest，解析文件及分块位置。
4. 从 Steam 内容分发节点读取内容块。
5. 使用对应 depot key 解密，再解压 VZ / VZstd 等载荷。
6. 将块写入目标文件的指定偏移，并追加完成记录。
7. 所有必需文件完成后，登记安装元数据。

内容块的完整性判断与清单对应；暂停或退出时保留已完成块的记录。续传使用保存的计划和清单，不从头开始整款游戏。

## 文件名、IV 与加密内容

Steam 内容格式中的 IV 与数据一起编码，不能统一替换成全零。实现按格式取出加密 IV，使用相应密钥恢复 IV，再处理后续内容。Lua 只是元数据的文本载体，与文件块加密是两层不同的处理。

## 安装位置与恢复

游戏文件进入选择的游戏库下的 `steamapps/common`。任务计划、块记录和缓存位于 Bear 的 `data`。完成后写入 Steam 安装元数据；这一步只描述磁盘上的安装状态，不授予账号许可。

删除未完成任务时先停止对应工作进程，再按用户选择移除任务记录或未完成文件。已登记安装的内容按保留规则处理。

## 网络层

代理配置优先。未使用代理时可尝试本地 SNI 模式：连接目标节点、在 TLS 握手中省略域名 SNI，但 HTTP Host 和证书名称认证仍使用原始域名。无法通过认证的连接不会继续传输内容。

公开源码不包含运营环境的上游适配器、账号令牌、默认资料服务地址或资料收集脚本。
